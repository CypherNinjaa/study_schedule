Storage & autosave

Your entire workspace lives in one JSON file on your device. This page explains how it's saved, what happens automatically, and what to do if the connection to the file is ever lost.

Everything is one JSON file

All of it — profile, settings, timetable, tasks, study sessions, habits, XP, streaks, achievements, goals, notes — is stored in a single structured JSON file, for example productivity-data.json. Because it's plain text, you can read it in any editor, copy it to a USB drive, email it to yourself, or keep it in a synced folder. You own it completely.

The file is versioned. It carries a schema version number so that future updates to the app can safely understand and upgrade files created by older versions.

How autosave works

You never have to press save. The moment you change anything — complete a task, log a study session, edit your timetable — the app:

  1. Updates instantly

    The change appears on screen immediately and is marked as "unsaved".

  2. Waits a beat

    A short debounce (under a second) batches rapid edits together so it isn't writing on every keystroke.

  3. Writes to your file

    The indicator shows "Saving…", then "Saved ✓" once the write completes.

Writes are also flushed when you switch away from the tab or close it, so a change made a split second before closing still lands safely.

The two storage modes

Depending on your browser and your choice during setup, the app saves in one of two ways:

File mode (recommended)

Available in Chrome and Edge on desktop. Using the browser's File System Access API, the app writes directly to the .json file you chose. The file on disk is always the source of truth, and a copy is also mirrored inside the browser as a safety net.

Browser mode (fallback)

If your browser can't write files directly, or you chose "just use this browser," your data is stored inside the browser using IndexedDB. It's still private and persists between sessions — but it lives in that browser profile, so it won't appear if you switch browsers or clear site data. In this mode, use Download backup regularly and keep the file somewhere safe.

"File disconnected" — what it means

Browsers sometimes drop write permission to a file — for instance after a restart, or if the file was moved. When that happens the indicator shows File disconnected. Nothing is lost: the app keeps saving to its in-browser mirror in the meantime.

To restore the direct file connection, click the indicator (or use Reconnect in Settings) and grant permission again. The app compares the file on disk with its mirror and keeps whichever is newer, so you never lose the latest work.

If reconnecting keeps failing

Your data is safe in the browser regardless. Download a backup immediately, then see Troubleshooting for step-by-step recovery.

Backups, import, and export

Independent of autosave, you can always take a manual snapshot:

  • Download backup — saves a timestamped copy of your complete data as a .json file.
  • Export — the same complete data, for moving to another device or archiving.
  • Import — load a previously exported/backed-up file. Handy when moving from browser mode to file mode, or to a new computer.

All of these live on the Settings page and in the command palette. For the privacy guarantees around all of this, see Privacy & data safety.
